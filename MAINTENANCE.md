
# Small Business Website Maintenance Schedule

Regular website maintenance helps small businesses keep their websites secure, functional, accurate, and useful for visitors. This schedule provides a practical starting point for routine checks.

## 1. Weekly Website Checks

- [ ] Open the main website pages and check that they load correctly.
- [ ] Test contact forms and confirm that submissions are received.
- [ ] Check important buttons, phone links, and email links.
- [ ] Review the website for outdated information or obvious display problems.
- [ ] Check for security alerts and unusual website activity.
- [ ] Review website backups and confirm that recent backup jobs completed successfully.

## 2. Monthly Website Checks

- [ ] Review website software, themes, and plugin updates.
- [ ] Apply updates after checking compatibility and confirming a recovery plan.
- [ ] Review website performance using [PageSpeed Insights](https://pagespeed.web.dev/).
- [ ] Check for broken links on important pages.
- [ ] Review website traffic and important conversion actions, if analytics is configured.
- [ ] Check that important pages remain accessible to search engines.
- [ ] Review administrator accounts and remove access that is no longer needed.
- [ ] Review the website's key content for accuracy.

## 3. Quarterly Website Checks

- [ ] Test the backup restoration process.
- [ ] Review user permissions and security settings.
- [ ] Check mobile layouts across important pages.
- [ ] Review accessibility, including keyboard navigation and form labels.
- [ ] Review important redirects, canonical URLs, and sitemap availability.
- [ ] Check whether service pages, prices, contact details, and business hours need updating.
- [ ] Review website goals and identify improvements based on visitor needs.

## 4. Before Updating WordPress

For WordPress websites, follow a careful update process.

- [ ] Check the update notes and compatibility information.
- [ ] Confirm that a recent backup is available.
- [ ] Test major or potentially disruptive updates on a staging site when possible.
- [ ] Apply updates and check the website afterward.
- [ ] Test important forms, navigation, and business functions.
- [ ] Investigate any errors before considering the update complete.

Avoid installing updates blindly on a business-critical website. A tested recovery plan helps reduce the risk of extended downtime.

## 5. When Something Goes Wrong

If a website develops a problem:

1. Record what happened and when it started.
2. Check recent updates and configuration changes.
3. Determine whether visitors, forms, payments, or other important functions are affected.
4. Follow the site's backup and recovery procedure when necessary.
5. Contact the responsible developer or hosting provider if the issue cannot be resolved safely.
6. Document the cause and the solution to help prevent recurrence.

## 6. Keep a Maintenance Log

Record completed tasks and any problems that need follow-up.

| Date | Task | Result | Follow-up |
|---|---|---|---|
| YYYY-MM-DD | Backup check | Completed or issue found | Record next action |
| YYYY-MM-DD | Form testing | Working or issue found | Record next action |
| YYYY-MM-DD | Software updates | Completed or postponed | Record next action |

## How to Use This Schedule

Adapt the frequency of checks to the website's platform, traffic, business importance, and security requirements. Websites that handle payments or sensitive information may need more frequent monitoring and additional security controls.

This schedule is a starting point, not a substitute for a security plan, professional technical support, or platform-specific maintenance instructions.
